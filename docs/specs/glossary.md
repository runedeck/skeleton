# Glossary

A specification marks a term it defines in *italics* the first time it uses it. Every marked term has an entry here. The rune CLI's house lint (CLI-0040) reports a marked term with no entry, through the `rune-spec-doctor` hook once a pinned rune release joins the tool versions.

- **agentic review lanes**: the automated reviewers that examine a pull request. Each lane is a distinct harness and model and reports one check run. Free lanes (Codex, Cursor Security) run on every push. The paid lane (Runeseer) runs only when the controller's triage admits a ready or green head, or when the owner forces it by label. CodeRabbit and Macroscope are optional summoned lanes. Every lane is a vendor product and none is required by the ruleset.
- **review funnel**: the ordered run of agentic review lanes on one pull request. Free lanes fill the ledger on every push. The paid adjudicator runs after the ready event, judges the range since the last verdict, and disposes of every ledger thread. The owner enters twice, at the open-seal and at the merge-seal.
- **trailer**: a `Key: value` line in the last paragraph of a commit message, as `git interpret-trailers` reads it. `Co-Authored-By` trailers name model contributors. `Resolves-Thread` trailers name review threads a fix answers.
- **merge base**: the most recent commit that a pull request head and its base branch both descend from, as `git merge-base` reports it. The commits a pull request introduces are the range from that commit to the head.
- **ledger**: the per-pull-request record the controller workflow owns: `reviewed_sha`, a generation counter, a status for every expected lane, and every review thread with its disposition. Built from the platform API by lane login, never from the resolved flag. Any new thread or lane status change increments the generation. The ledger is an artifact, and its public record is a check run named `ledger` on `reviewed_sha` under the reviewing identity, whose first line names the artifact, its sha256 digest, the generation, and the pull request.
- **open-seal**: an empty commit beneath a pull request head, signed with the owner's hardware key by `rune sign open`, whose message binds the repository, base ref, head tree, and a single-use nonce. Flipping a draft ready writes the nonce into the body. Proves the owner put their name on this pull request.
- **merge-seal**: an empty commit above `reviewed_sha`, signed with the owner's hardware key by `rune sign next`, with the same tree as its parent and the ledger generation and digest in its message. Proves the owner authorized this exact reviewed head and ledger to merge. A later push, generation bump, or rebuilt ledger unseals it.
- **controller**: the fixed workflow, owned by the ceremony and not by any vendor, that builds the ledger, runs the triage, invites the paid lane, and reports `review/correctness`. It bounds paid spend to three rounds per work item.
- **work item**: the change identifier a pull request names in its body (`docs/changes/<id>`), or the pull request number when it names none. The paid budget is keyed to it, so a replacement pull request does not reset the count.
